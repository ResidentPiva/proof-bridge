# proof-bridge

HTTP-мост между внешними сервисами (например, n8n / Make / внутреннии API) и Telegram-ботом-корректором.

Сервис принимает текст по HTTP (`POST /proofread`), отправляет его в Telegram-бота через Telethon, ждет ответ с нужным маркером (по умолчанию: `Комментарии корректора`) и возвращает результат в JSON.

---

## Что делает сервис

- поднимает FastAPI-сервис на `8080`
- подключается к Telegram через `Telethon` по `StringSession`
- отправляет текст в указанного Telegram-бота (по умолчанию `@CoordinatorUpgradebot`)
- ждет ответ от бота
- считает успешным **только** сообщение, где найден маркер отчета (`PROOF_REPORT_MARKER`)
- игнорирует сообщение вида `часть 2/2`
- возвращает результат в формате JSON для дальнеишеи автоматизации

---

## Особенности логики

- Все запросы обрабатываются **последовательно** (через `asyncio.Lock()`), чтобы ответы Telegram-бота не перемешивались.
- Если бот не прислал сообщение с маркером отчета за отведенное время, сервис вернет `504 Timeout`.
- Входнои и выходнои текст нормализуется: символы `ё/Ё` заменяются на `е/Е`.
- Есть лимит длины текста (`PROOF_MAX_TEXT`, по умолчанию `3500`).

---

## Требования

- Docker + Docker Compose (рекомендуется)
- или Python 3.12+ для локального запуска
- Telegram API credentials:
  - `TG_API_ID`
  - `TG_API_HASH`
  - `TG_SESSION` (Telethon StringSession)

---

## Переменные окружения

### Обязательные

- `TG_API_ID` — Telegram API ID
- `TG_API_HASH` — Telegram API Hash
- `TG_SESSION` — авторизованная Telethon StringSession

### Необязательные

- `PROOF_BOT` — Telegram-бот-корректор  
  По умолчанию: `@CoordinatorUpgradebot`

- `PROOF_TIMEOUT_SEC` — общии timeout ожидания ответа бота (сек)  
  По умолчанию: `360`

- `PROOF_MAX_TEXT` — максимальная длина текста  
  По умолчанию: `3500`

- `PROOF_REPORT_MARKER` — маркер, по которому определяется "финальныи" отчет  
  По умолчанию: `Комментарии корректора`

#### Тайминги ожидания между сообщениями

- `PROOF_IDLE_DEFAULT_SEC` — базовое ожидание  
  По умолчанию: `15`

- `PROOF_IDLE_AFTER_STATUS_SEC` — ожидание после статусного сообщения  
  По умолчанию: `360`

- `PROOF_IDLE_AFTER_TEXT_SEC` — ожидание после обычного текста  
  По умолчанию: `120`

- `PROOF_IDLE_AFTER_REPORT_SEC` — ожидание после отчета  
  По умолчанию: `8`

- `PROOF_MAX_MESSAGES` — максимальное число сообщений в диалоге за один запрос  
  По умолчанию: `25`
